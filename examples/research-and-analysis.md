# Research and analysis

Illustrative scenario using hypothetical source versions, not a product claim.

A team is comparing storage services. A prior conclusion says feature X is not
available in the required region, based on official documentation from March.
A September release note says regional support has changed.

```text
Use $opus-mode-for-codex.
Continue the comparison. Keep our region, retention, and budget constraints.
Reconcile the new release note with the earlier availability conclusion.
```

Read the current primary documentation and the dated release note. Check whether
the change is generally available, a preview, or limited to another tier. Revise
the earlier conclusion only to the extent supported, and revisit recommendations
that depended on it. Retain the still-valid retention and budget constraints.

The output should explain the changed evidence, its date and scope, the resulting
recommendation, and any unresolved availability question. It should not simply
append the release-note link to an unchanged answer.

Stop once further browsing is unlikely to change the decision. If a material
point remains unknown, identify that gap instead of manufacturing certainty.
